1. System overview

DeerFlow embeds a LangGraph super-agent in the Gateway (app/gateway) and exposes Model Context Protocol servers as ordinary agent tools plus a separate durable runtime for long-running remote work. The harness owns protocol, pooling, caching, and auth; the app owns HTTP deployment APIs, per-user personal servers, and the task service that runs outside the LLM loop.

3. Request paths

3.1 Discovery (lazy, cached)

initialize_mcp_tools() reads one ExtensionsConfig snapshot and calls get_mcp_tools(). Tools publish only if the effective MCP slice that produced them still equals the current slice, closing the superseded-revision window. A skills-only edit adopts the new file signature and keeps pooled sessions.

3.2 Ordinary tool call

Stdio calls reuse the pooled session for (server, scope, loop, domain) with thread-workspace cwd and TMPDIR pinned under workspace/.mcp/tmp/; SSE/HTTP calls are ephemeral with per-call timeouts. Interceptors resolve credentials on every call. Connection closed evicts only the session that failed; timeouts and isError results do not.

3.3 Durable task call

Submit is awaited inside the agent run and persists a bounded row (errors capped at 4,000 chars; artifacts at 64 KiB). Status and cancel run after the run ends under static/OAuth or the persisted owner's credential. Poll timestamps use remote completion time; transient errors back off without a max attempt count; five notification failures stop retries. Cancel of an in-flight poll releases only the fenced lease.

4. Cache invalidation and reconciliation

Stage one compares resolved path plus (mtime, size, sha256) signature, catching same-second edits, backward mtime moves, and file swaps. Stage two serializes the effective MCP slice (enabled servers in order plus mcpInterceptors) and retires state only when that slice changed. Claims install the recorded revision; unchanged stdio bindings survive while changed or removed ones advance epochs or take tombstones. Gateway writers use prepare_mcp_reconciliation() then finish_mcp_reconciliation(); failure falls back to a conservative full reset and a 500.

5. Auth precedence and stdio safety

Header precedence is static headers < OAuth < user_auth < headers_from_context, applied through case-insensitive override so a stale authorization spelling cannot shadow the winner. Missing or transport-illegal values fail closed without echoing secrets. At the HTTP boundary, API-registered stdio servers must name a bare allowlisted launcher (npx, uvx plus DEER_FLOW_MCP_STDIO_COMMAND_ALLOWLIST), avoid exec args and code-injecting env names, with package-launcher option-region screening. This is defense in depth; npx/uvx still fetch remote code, so admin auth remains the real boundary.

8. Limits and open questions

  • No spark-mcp implementation exists here; if the request meant an external Spark MCP server, its code was not in this checkout.
  • Durable recovery needs a SQL backend; the in-memory backend leaves the task repository unavailable.
  • Per-request secrets cover submit but not later background polls, which is flagged at startup.
  • Users cannot submit an answer back to an input_required remote task in the current driver.
